# Follow-up register

This is the one register of every follow-up the Orbit parity program has raised: the Known gaps in
[untrusted-repositories.md](untrusted-repositories.md), the follow-ups of every pull request, and the open items of each
milestone's verification rounds. It covers milestones M1 and M2, the M3 task pull requests, M3 verification rounds 1
to 9, and the rows that M4 task pull requests raise and close. The class numbers are the classes of
[untrusted-repositories.md](untrusted-repositories.md).

## How a row moves

- Every follow-up has one row with a stable id, `FU-<milestone>-<nnn>`, where the milestone is the one it was first
  raised in. The same defect found again, or worded differently, is one row that lists every source and keeps the status
  and carrier of the latest check; the other ids are in "Duplicates", each with the row it was merged into.
- A row is **open** (it names a carrier: a plan task id, `sweep` for work no task owns, or `owner`), **owner**
  (it waits for a decision, one line below), **fixed**, or a **duplicate**.
- A **fixed** row names the commit and the test that pins it. A row with no commit stays open, and so does a code fix that
  no test pins ("Fix not pinned by a test", carrier `sweep`). A fix to a document, a comment, a build file or the tests
  themselves says "none needed" or "the fix is the test" and why. When a later round finds a fix reverted, the row is open
  again and says so (FU rows with "reopened" in their source).
- Each milestone's verification adds its rows and updates the statuses it checked. A task that carries a row closes it in
  its own pull request: it moves the row to "Fixed" with the commit and the test.
- Severity is the severity the checking round gave it. "Open majors" lists every open row of severity major, whatever
  its carrier, and those rows are not repeated in the milestone tables. "For the owner" holds the rows whose status is
  owner (they wait for a decision before anyone can build); an open row whose carrier is `owner` has no plan task and
  sits in the last open table.
- A carrier is a plan task id. Three tasks (`clients-ux-8`, `clients-ux-26`, `agents-extensibility-34`) appear in the plan
  only by their short ids (CU8, CU26, AE34).
- The evidence column of an open row says where the defect is (file and line) as the triage found it. The follow-ups of
  M3 verification rounds 7 to 9 and every fixed row were re-checked against the tree at `bcfcfd7` (the head of
  `m3-integration` when this register was written): a fixed row's commit is an ancestor of that head, and its test
  name is in the tree where the evidence gives one. Five rows that an earlier round called fixed were reopened because
  the anti-loop reverts of rounds 8 and 9 (`e94ae2f`, `4c88f0b`) removed their code and tests: three are open rows
  (FU-M3-242, FU-M3-288, FU-M3-290) and two became duplicates of them. Line numbers into
  [untrusted-repositories.md](untrusted-repositories.md) and [known-failures.md](known-failures.md) were adjusted for the
  lines this pull request adds to them; a heading cited by name does not move.
